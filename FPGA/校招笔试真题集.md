## 一、经典高频笔试题（各公司反复考，含解析）

### 1.1 建立时间计算与最高频率（⭐⭐⭐⭐）

**知识点**：`setup/hold`、`时序`

**题干**：两级触发器之间组合逻辑最大延迟 4ns，触发器 $t_{co}=1\text{ns}$、$t_{su}=1\text{ns}$、$t_h=0.5\text{ns}$，时钟周期 10ns，忽略 skew。问：是否违例？最高工作频率？

**答案**：不违例；$f_{max} \approx 166.7\text{MHz}$。

**解析**：
$$T_{min} = t_{co} + t_{comb} + t_{su} = 1+4+1 = 6\text{ns} \le 10\text{ns} \text{ ✓}$$
$$f_{max} = 1/T_{min} = 1/6\text{ns} \approx 166.7\text{MHz}$$
hold 检查：$t_{co(min)} + t_{comb(min)} \ge t_h$，与频率无关，只要路径最小延迟够即可（一般组合路径最小延迟 ≥ 0）。

### 1.2 阻塞/非阻塞赋值结果（⭐⭐⭐）

**知识点**：`Verilog`、`阻塞/非阻塞`

**题干**：初始 $a=1,b=0$，上升沿后下面两段代码 $a,b$ 分别是什么？

```verilog
// 代码1
always @(posedge clk) begin
    a <= b;
    b <= a;
end
// 代码2
always @(posedge clk) begin
    a = b;
    b = a;
end
```

**答案**：代码1 → $a=0,b=1$（交换）；代码2 → $a=0,b=0$。

**解析**：非阻塞 `<=` 并行取旧值，所以 a 拿 b 旧值 0、b 拿 a 旧值 1，交换；阻塞 `=` 顺序执行，a 先变 0，b 再取"已经变过的 a"=0。**时序逻辑里用阻塞赋值会仿真/综合不一致**，这是经典反例。

### 1.3 FIFO 深度计算（⭐⭐⭐⭐⭐）

**知识点**：`FIFO 深度`、`CDC`

**题干**：写时钟 100MHz 背靠背突发写 200 个数据，读时钟 80MHz 连续读，问 FIFO 最小深度。

**答案**：40。

**解析**：突发时长 $T = 200/100\text{M} = 2\mu\text{s}$，期间读走 $80\text{M}\times2\mu\text{s}=160$ 个，深度 $=200-160=40$。公式见 [[FPGA/FPGA校招面试八股.md|八股]] 7.2 节。

### 1.4 占空比 50% 的三分频（⭐⭐⭐⭐）

**知识点**：`分频`、`Verilog`

**题干**：写出占空比 50% 的三分频器代码。

**答案**：模 3 计数器，上升沿/下降沿各产生 `(cnt==0)` 脉冲，相或：

```verilog
reg [1:0] cnt_p, cnt_n;
always @(posedge clk or negedge rst_n)
    if (!rst_n) cnt_p <= 0; else cnt_p <= (cnt_p==2)?0:cnt_p+1;
always @(negedge clk or negedge rst_n)
    if (!rst_n) cnt_n <= 0; else cnt_n <= (cnt_n==2)?0:cnt_n+1;
assign clk_out = (cnt_p==0) | (cnt_n==0);
```

### 1.5 推断出 latch 的代码（⭐⭐⭐）

**知识点**：`Verilog`、`latch`

**题干**：下面代码综合出什么电路？

```verilog
always @(*) begin
    if (en) y = d;
end
```

**答案**：推断出 **latch**（en=0 时 y 保持）。

**解析**：组合 always 中 `if` 无 `else` → 未写分支保持旧值 → 综合器用锁存器实现。应补 `else y = 1'b0;`。

### 1.6 跨时钟域单比特处理（⭐⭐⭐）

**知识点**：`CDC`

**题干**：慢时钟域的单比特电平信号传到快时钟域怎么处理？快→慢的窄脉冲呢？

**答案**：慢→快：打两拍即可；快→慢：窄脉冲可能短于慢周期而漏采，需**脉冲同步器（toggle 法）**或**展宽+握手**。详解见 [[FPGA/FPGA校招面试八股.md|八股]] 4.2 节。

### 1.7 序列检测 1011（⭐⭐⭐⭐）

**知识点**：`状态机`、`FSM`

**题干**：设计可重叠的 1011 序列检测器（Moore），画出状态转移关系。

**答案**：$S_0 \xrightarrow{1} S_1 \xrightarrow{0} S_2 \xrightarrow{1} S_3 \xrightarrow{1} S_4$（$S_4$ 输出 1）；重叠：$S_4 \xrightarrow{1} S_1$、$S_4 \xrightarrow{0} S_2$。完整代码见 [[FPGA/FPGA校招面试八股.md|八股]] 6.4 节。

**1. 时钟 jitter 和时钟偏斜的概念，以及它们影响 FPGA 的最高工作频率吗？（⭐⭐⭐⭐）**

**知识点**：`skew`、`jitter`、`时序`

**答案**：
- **时钟偏斜 skew**：同一时钟源到达**不同触发器**的时间差。根源是时钟布线长度不同（走线有延迟），所以"同一个沿"到 A 触发器和 B 触发器时刻不一致。它是**空间（芯片位置）维度的偏差**。
- **时钟抖动 jitter**：时钟边沿相对理想时刻的**随机偏差**。根源是 PLL/MMCM 的相位噪声、电源纹波、温度漂移。它是**时间（同一位置不同时刻）维度的不确定**，同一时刻看单个 FF 的沿也在抖。

**它们影响最高频率吗？—— 都影响**，机理不同：

| 因素 | 对 setup 的影响 | 对 hold 的影响 | 净效果 |
|------|----------------|---------------|--------|
| skew（负偏斜，接收端时钟**早到**） | 吃掉建立余量 | 有利于保持 | **降低**最高频率 |
| skew（正偏斜，接收端时钟**晚到**） | 增加建立余量 | 威胁保持 | 可能提高 setup 上限，但 hold 变紧 |
| jitter | 压缩有效周期 | — | 一定**降低**最高频率 |

setup 分析公式（保守把 skew/jitter 都加进去）：
$$T_{clk} \ge t_{co} + t_{comb} + t_{su} + t_{skew} + t_{jitter}$$

**符号含义**（记忆：沿 1 出发 → 传数据 → 赶在沿 2 前稳定，一共只有 $T_{clk}$）：

| 符号 | 全称 | 含义 |
|------|------|------|
| $T_{clk}$ | 时钟周期 | 倒数即最高频率 $f_{max}=1/T_{clk}$ |
| $t_{co}$ | clock-to-output | 发送触发器的输出延迟：时钟沿到后 Q 端出数据的时间 |
| $t_{comb}$ | 组合逻辑延迟 | 数据穿过中间所有 LUT/布线的总延迟 |
| $t_{su}$ | 建立时间 | 接收触发器要求数据提前于时钟沿稳定 |
| $t_{skew}$ | 时钟偏斜 | 时钟到收发两个触发器的时间差（空间偏差） |
| $t_{jitter}$ | 时钟抖动 | 时钟沿随机偏差，等效压缩周期（时间偏差） |

**时间线**：时钟沿 1 →（$t_{co}$）发送 FF 输出 →（$t_{comb}$）组合逻辑 → 接收 FF 的 D 端 → 须在时钟沿 2 前 $t_{su}$ 稳定；沿 1→沿 2 总长 $T_{clk}$，再留 skew/jitter 余量。

所以**结论：都会影响最高工作频率**。jitter 只有坏影响；skew 方向不定，设计按最坏情况处理。**回答要点**：先把两者概念讲清（空间 vs 时间），再分别说它们怎么进时序公式。

**2. 建立时间和保持时间的概念，以及出现违例怎么修复？（⭐⭐⭐⭐⭐）**

**知识点**：`setup/hold`

**答案**：
- **建立时间 $t_{su}$**：时钟沿**到来前**，数据必须提前稳定下来的最小时间。它限制了数据能"走多慢"。
- **保持时间 $t_h$**：时钟沿**到来后**，数据必须继续保持不变的最小时间。它限制了数据能"变多快"。

**setup 违例**（数据到得太晚）——**影响：限制最高工作频率**（路径太长，数据来不及在下一个沿前稳定，频率一高就出错，所以"最高频率上不去"）。修复：
1. **降频**（增大 $T_{clk}$），最直接；
2. **插流水线**：在组合路径中间切一级 FF，把 $t_{comb}$ 切成两半（面积换速度）；
3. **逻辑优化**：减少组合级数、把大表达式拆小、用查找表替换；
4. **综合/布局优化**：提高综合 effort、约束布局、寄存器重定时 retiming；
5. 减小 skew。

**hold 违例**（数据变得太快）——**影响：功能性错误，与频率无关**（数据在同一个时钟沿后没保持住 $t_h$，接收端采到的是"变掉的值"，即使降频也照样错）。修复：
1. **数据路径加 buffer 延迟**（在布线工具里加 delay cell / buffer）；
2. 工具里开 hold 修复选项；
3. 注意：**hold 与频率无关**，降频救不了 hold 违例——因为 hold 检查的是"同一个沿后数据不能马上变"，时钟周期再大也没用。

> **插 buffer 是什么？和"打拍"有什么区别？（面试高频追问）**
>
> **打拍** = 在路径上插入**触发器 FF**（有时钟）：把组合路径切短，数据**晚一个时钟周期**到 → 修 **setup 违例**。
> **插 buffer** = 在路径上插入**延迟单元**（如两个反相器串联的 buffer，无时钟）：加一点**纯传播延迟** $\Delta t$，数据**慢几纳秒**到、不多占周期 → 修 **hold 违例**。
>
> 一句话：**打拍=加停顿站（修 setup，但加 1 拍延迟）；插 buffer=加绕路（修 hold，只吃面积/时序余量）**。二者不能互换——打拍对 hold 无效，插 buffer 反而恶化 setup。FPGA 中 hold 一般由布线工具自动修复，不必手插。

判断违例看 **timing report 的 WNS/TNS**（负值即违例）。

**3. BRAM 和分布式 RAM 的区别？什么情况优先选哪个？（⭐⭐⭐⭐）**

**知识点**：`BRAM`、`分布式 RAM`

**答案**：

| 对比项 | BRAM | 分布式 RAM |
|--------|------|------------|
| 物理实现 | 专用硬核存储块（7 系每块 36Kb） | 用 **LUT** 拼出来的存储 |
| 容量 | 大（几 Kb～几十 Mb） | 小（几十 bit～几 Kb） |
| 读写 | 同步写、同步读（有寄存器输出，读延迟固定 1~2 拍） | 同步写、**可异步读**（也可同步） |
| 资源成本 | 占专用 BRAM 块 | 占 LUT/FF（与逻辑争资源） |
| 端口 | 每块有限（一般 2 端口） | 灵活，可拆成多个小端口 |
| 时序 | 时序友好，不占逻辑资源 | 容量大时占用 LUT 多、时序变差 |

**选择原则**：
- **大容量、规整、需要同步读的存储**（数据缓冲、图像行缓存、跨时钟 FIFO 体）→ **BRAM**；
- **小容量（≤ 几 Kb）、需要异步读、或 BRAM 已用尽** → 分布式 RAM；
- **小移位寄存器 / 小 FIFO / 延迟线** → 分布式（SRL16 就是 LUT 改的移位寄存器）；
- **海量小存储分散在逻辑中** → 分布式更省 BRAM。

一句话：**大而规整用 BRAM，小而灵活用分布式**。

**4. IOBUF、IDELAY、IDDR、ODDR 是什么？应用场景？（⭐⭐⭐⭐）**

**知识点**：`IO 原语`

**答案**：

| 原语         | 全称/作用      | 关键点                                       | 应用场景                                         |
| ---------- | ---------- | ----------------------------------------- | -------------------------------------------- |
| **IOBUF**  | 双向 IO 缓冲器  | 三态控制（高阻 Z / 输出 / 输入），一个 pin 双向            | I2C 的 SDA、存储器数据线等 **inout 总线**               |
| **IDELAY** | 输入可编程延时单元  | 对输入信号做精细延时（步进几十 ps，由 tap 控制）              | 对齐源同步接口的 **per-bit skew**（DDR 数据线、LVDS 串行数据） |
| **IDDR**   | 输入 DDR 寄存器 | 时钟**上、下沿各采 1 bit**，把 1 路 DDR 转成 2 路并行（半速） | DDR 接口**接收**，如 DDR3/4 数据读                    |
| **ODDR**   | 输出 DDR 寄存器 | 把 2 路并行数据在**上、下沿分别输出**，合成 1 路 DDR         | DDR 接口**发送**、DDR 时钟输出（如 DQS 发射）              |

**串联一句话**：**IDDR/ODDR 负责串并/并串转换（DDR 收发）**，IDELAY 负责输入对齐（解决源同步接口的 bit-skew），IOBUF 负责双向总线。写 DDR 接口或高速源同步接口时这四样是标配。

**5. 竞争和冒险的概念、怎么判断、怎么消除？（⭐⭐⭐⭐）**

**知识点**：`竞争冒险`

**答案**：
- **竞争（race）**：同一信号经**不同路径**（不同门延迟）到达汇合门，各路径延迟不同，到达时刻不一致。
- **冒险（hazard）**：竞争导致输出出现**违背稳态逻辑的瞬时毛刺**。分两类：
  - **静态 1 冒险**：输出本应恒 1，却瞬时掉到 0（负脉冲），对应 $Y=X+\overline{X}$ 形式；
  - **静态 0 冒险**：输出本应恒 0，却瞬时跳到 1（正脉冲），对应 $Y=X\cdot\overline{X}$ 形式。

**判断（三种方法）**：
1. **代数法**：把其余变量代入固定值，若表达式能化成 $X+\overline{X}$ → 1 型冒险；化成 $X\overline{X}$ → 0 型冒险。
2. **卡诺图法**：两个积项圈**相切不相交**处，就是冒险点。
3. **波形观测**：示波器/仿真看跳变瞬间是否出现毛刺。

**消除（四种手段 + 原理）**：
| 手段 | 原理 |
|------|------|
| 加**冗余乘积项** | 桥接相切圈，过渡期托住输出（最治本） |
| 输出**并联电容** | 低通滤掉窄毛刺（低速可用） |
| **选通脉冲** | 避开瞬态，只采稳态 |
| **输出加同步寄存器** | 时钟沿屏蔽沿间毛刺——**FPGA 最常用** |

**6. reg 和 wire 区别？reg 不赋初值综合后电路什么样？（⭐⭐⭐）**

**知识点**：`Verilog`

**答案**：
- **wire**：线网类型，由 `assign` 或模块端口连续驱动，表示物理连线。
- **reg**：变量类型，由 `always` 块过程赋值。**关键：reg 不一定是寄存器**——
  - `always @(posedge clk)` 里的 reg → 综合成**寄存器（FF）**；
  - `always @(*)` 里的 reg → 综合成**组合逻辑**；
  - 组合 always 里 if/case 分支不全 → 综合成 **latch**。

**不赋初值综合后**：
- 仿真中：reg 默认是 **X**，参与运算会把 X 传染。
- 综合后上电：寄存器的初始状态是**随机的/不定**（取决于 FPGA 配置后 FF 的实际状态）。
- **后果**：计数器/状态机可能从任意状态起跑 → 表现为"随机复位/数据错误"。
- **对策**：**必须复位初始化**——异步复位、同步释放，或复位时赋初值。这是"随机复位/数据错误"类问题的第一大嫌疑。

**7. case 有 default 的好处？没有 default 综合会怎样？（⭐⭐⭐）**

**知识点**：`Verilog`

**答案**：
- **default 的好处**：
  1. 覆盖未列举的编码，**避免推断出 latch**（组合 case 未穷举时保持旧值）；
  2. 状态机的**非法状态有去处**（归到 IDLE），防止跑飞；
  3. **仿真与综合一致**（未加 default 时两者行为可能不同）。
- **没有 default**：
  - 组合 case 未穷举（如 2bit 只写 00/01/10 三支）→ 综合推断出 **latch**（那支保持旧值）；
  - 用于 FSM → 未定义编码没有转移，可能**进入非法状态**无法跳出。
- **建议**：每个 case 都写 default，即使已穷举（1bit 的 0/1）也写上，更安全、语义更清楚。

**8. 复杂 FPGA 项目随机复位/数据错误、无法复现，用什么方法/工具定位？（⭐⭐⭐⭐⭐）**

**知识点**：`Debug`、`CDC`

**答案**：随机、无法复现的错误，99% 与**异步/跨时钟/复位**有关，按"在线抓 → 工具扫 → 根源查 → 仿真复现"四步排查：

1. **在线抓信号（不打断运行）**：加 **ILA**（Vivado 逻辑分析仪核）抓关键信号——复位、PLL lock、FIFO 空满、状态机当前态、数据使能、错误标志；**VIO** 在线读写内部寄存器，现场注入/查询。
2. **扫跨时钟域（CDC）**：随机错误最典型来源。用 **Spyglass CDC / Vivado CDC 分析**扫未同步的跨域信号、亚稳态；重点查：单比特快慢域是否打拍、多比特是否握手/格雷码、异步 FIFO 空满是否保守。
3. **查复位与时钟**：
   - 复位：确认**异步复位、同步释放**；查复位树偏斜、漏复位模块、复位时序（是否在时钟建立后释放）；
   - 时钟：PLL/MMCM lock 是否稳定、有无时钟毛刺/切换、门控时钟。
4. **仿真复现**：抓取实际激励写 testbench；加 **SVA 断言**监控协议/时序违例；跑随机 seed 回归。
5. **现场留痕**：出错瞬间把关键状态/计数值/时间戳锁进**错误快照寄存器**，事后经接口读出，定位是哪一拍出问题。
6. **二分隔离**：把数据通路/控制通路、可疑模块逐个屏蔽，缩小范围。

**工具清单**：Vivado **ILA / VIO / IBERT**、VCS/XSim + SVA、**Spyglass CDC**、逻辑分析仪、Xilinx Debug Hub。

**9. 编程题：0~255 计数器，有效时计数、无效保持，255→0 时输出一个时钟周期的溢出脉冲（⭐⭐⭐⭐⭐）**

**知识点**：`计数器`、`Verilog`

**答案**：

```verilog
module cnt_ovf (
    input  clk,
    input  rst_n,
    input  en,            // 有效计数，无效保持
    output reg [7:0] cnt, // 0~255
    output reg ovf        // 255→0 那一拍，输出一个周期高电平
);
    always @(posedge clk or negedge rst_n)
        if (!rst_n) begin
            cnt <= 8'd0;
            ovf <= 1'b0;
        end
        else if (en) begin
            cnt <= cnt + 1'b1;
            ovf <= (cnt == 8'd255);   // 本拍 cnt 由 255 变 0，输出溢出脉冲
        end
        else begin
            cnt <= cnt;               // en 无效：保持
            ovf <= 1'b0;
        end
endmodule
```

**解析**：
- **计数**：`en` 为 1 时 `cnt <= cnt+1`，0~255 循环；`en` 为 0 时 `cnt <= cnt` 保持。
- **溢出脉冲**：`ovf <= (cnt==255)`——当本拍旧值 cnt=255 且 en=1 时，这一拍 cnt 变为 0、ovf 变为 1；下一拍 cnt=0 时 `ovf<=0`。所以 `ovf` 恰好高一个时钟周期，且正是在 255→0 跳变后的那一拍。
- **边界**：复位后 cnt=0 不立即输出脉冲；en 保持有效时每 256 拍出一次溢出。
- 已用仿真验证：`ovf` 只在 255→0 那一拍为高，宽恰为 1 个时钟周期。
