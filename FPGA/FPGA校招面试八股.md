## 一、FPGA 架构与基本概念

### 1.1 FPGA 是什么？与 ASIC/MCU/GPU 的区别

FPGA（Field Programmable Gate Array，现场可编程门阵列）是**可通过编程配置硬件结构**的芯片，本质是"用可编程的连线把大量可编程逻辑单元连成你想要的电路"。

| 对比 | FPGA | ASIC | MCU | GPU |
|------|------|------|-----|-----|
| 本质 | 硬件可编程 | 硬件固化 | 软件跑在固定硬件上 | 大规模并行计算单元 |
| 灵活性 | 高，可重配置 | 低，流片后不可改 | 高（软件） | 中 |
| 性能/功耗 | 中 | 最优 | 低 | 高（吞吐） |
| 成本 | 单片贵、无 NRE | NRE 极高、量大便宜 | 低 | 中 |
| 上市周期 | 短 | 长 | 中 | 中 |
| 典型场景 | 原型验证、通信、雷达、加速卡 | 手机 SoC、矿机 | 控制类 | AI 训练/推理 |

**一句话**：MCU 是"串行执行指令"，FPGA 是"并行执行硬件"；FPGA 的每个逻辑单元在同一时刻都在工作。

### 1.2 FPGA 内部资源（以 Xilinx 7 系/UltraScale 为例）

| 资源 | 作用 | 要点 |
|------|------|------|
| **LUT**（查找表） | 实现组合逻辑 | 7 系为 6 输入 LUT（LUT6），可拆成两个 LUT5；UltraScale 的 LUT6 有双输出（fracturable） |
| **触发器 FF**（Flip-Flop，即边沿 D 触发器） | 实现时序逻辑 | 每个 LUT 旁配一个 FF，组合+时序成对（SLICE） |
| **BRAM** | 块状存储 | 7 系每块 36Kb，可拆 2×18Kb；同步读写、有寄存器输出 |
| **分布式 RAM** | LUT 改配的小存储 | 异步读、同步写，适合小 FIFO/移位 |
| **DSP48** | 乘累加 | 内含乘法器+加法器+寄存器，适合滤波/FFT |
| **CMT（MMCM/PLL）** | 时钟管理 | 倍频/分频/移相/去抖动 |
| **IOB** | 输入输出 | 支持 DDR、多种电平标准 |
| **全局时钟网络 BUFG** | 低 skew 时钟分布 | 时钟必须走专用网络 |

**LUT 原理**：一个 n 输入 LUT 本质是 $2^n$ 位的小 **SRAM（Static RAM，静态随机存取存储器**——用双稳态电路存 1 bit，读写快、不用刷新，但掉电丢失）。把真值表存进去，输入当地址查表输出——**任何 n 输入组合函数都能用一个 LUT6 实现**。所以"LUT 即卡诺图/真值表"（呼应 [[FPGA/数字电路基础.md|数字电路基础]]）。

### 1.3 常见追问

- **Q：FPGA 上电后配置过程？** A：上电 → 读配置芯片（Flash）比特流 → 配置 SRAM（LUT/连线）→ DONE 拉高 → 开始工作。SRAM 型掉电丢失，所以每次上电都要重新配置。
- **Q：SLICE/CLB 是什么？** A：CLB 由若干 SLICE 组成，SLICE 含 4 个 LUT6 + 8 个 FF（触发器）（7 系），是布局布线的基本单位。
- **Q：BRAM 和分布式 RAM 怎么选？** A：大容量、规整存储用 BRAM；小容量、需要异步读/低延迟用分布式 RAM。

## 二、Verilog 编码与 RTL 思维

### 2.1 可综合 vs 不可综合

- **可综合**：always（带敏感列表规范）、assign、if/case、for（有限次展开）、模块实例化。
- **不可综合**（仅仿真）：initial、#延迟、$display、while（无限）、fork-join。

### 2.2 阻塞 = vs 非阻塞 <=

| | 阻塞 `=` | 非阻塞 `<=` |
|---|---|---|
| 语义 | 顺序执行，立即赋值 | 并行执行，块末统一更新 |
| 用途 | 组合逻辑 always @* | 时序逻辑 always @(posedge) |
| 混用后果 | 时序里用 = 产生竞争/仿真综合不一致 | 组合里用 <= 产生 latch/仿真差异 |

**黄金法则**：时序用 `<=`，组合用 `=`，**同一 always 块不混用**。

### 2.3 wire 与 reg

- `wire`：线网，由 assign 或模块端口驱动，表示物理连线。
- `reg`：变量，由 always 块赋值，**不一定是寄存器**——always @* 里的 reg 是组合，always @(posedge) 里的 reg 才是寄存器。

### 2.4 如何避免 latch

组合 always 块中 **if 没有 else、case 没有 default** 会推断出 latch（保持旧值）。危害：电平敏感、时序难控、毛刺敏感。避免：写全所有分支 + default。

### 2.5 常见追问

- **Q：always @* 和 always @(a or b) 区别？** A：@* 自动包含块内所有读取信号，不易漏；手写列表漏信号会出仿真综合不一致。
- **Q：function 和 task 区别？** A：function 无延时、必有一个返回值、组合；task 可含延时、多输出、可时序。
- **Q：parameter 和 localparam？** A：parameter 可被上层模块覆盖（defparam/#()），localparam 仅本模块内部。
- **Q：generate 用途？** A：批量例化/条件例化，如生成加法器链、参数化位宽。

## 三、时钟与复位

### 3.1 同步复位 vs 异步复位

| | 同步复位 | 异步复位 |
|---|---|---|
| 写法 | always @(posedge clk) if(!rst_n) | always @(posedge clk or negedge rst_n) |
| 优点 | 无复位毛刺、利于时序 | 不依赖时钟、复位快 |
| 缺点 | 需时钟存在、占逻辑 | 复位释放时刻不确定（可能违 setup/hold） |

**最佳实践：异步复位、同步释放**（复位树异步置位，释放用两级 FF（触发器）同步到时钟沿），兼顾两者优点。

```verilog
module reset_sync (
    input  clk,
    input  rst_n,      // 异步复位
    output rst_sync_n  // 同步释放的复位
);
    reg [1:0] sync;
    always @(posedge clk or negedge rst_n)
        if (!rst_n) sync <= 2'b00;
        else        sync <= {sync[0], 1'b1};
    assign rst_sync_n = sync[1];
endmodule
```

### 3.2 时钟网络

- 时钟必须走**专用全局网络（BUFG）**，不能用普通布线（skew 大、占 LUT）。
- **时钟不能直接门控/组合逻辑分频**（产生毛刺+skew），要分频用计数器寄存器输出或 MMCM。
- 多相位/倍频用 **MMCM/PLL**。

### 3.3 追问

- **Q：什么是时钟偏斜 skew、抖动 jitter？** A：skew = 同一时钟到不同 FF（触发器）的时间差；jitter = 时钟边沿相对理想位置的随机偏差。skew 影响 setup/hold 余量，jitter 压缩可用周期。
- **Q：复位树为什么要综合优化？** A：复位扇出大，需加 buffer/树形分布减小 skew。

### 3.4 时钟切换与门控

**时钟门控（Clock Gating）**：用使能信号控制时钟，空闲时不翻转，省动态功耗。但不能直接 `assign gclk = clk & en`——组合门控会在使能变化的瞬间产生毛刺。标准做法：**锁存器 + 与门**（使能先经电平敏感锁存器，只在 CLK 低电平期间更新，再与 CLK 相与）。

```verilog
reg en_l;
always @(en or clk)        // 锁存：CLK=0 时 en 透传
    if (!clk) en_l <= en;
assign gated_clk = clk & en_l;   // 使能只会在低电平期间变，无毛刺
```

**无毛刺时钟切换（Glitch-Free Clock Mux）**：在两个时钟源间切换（如切换 PLL 与外部时钟），直接 `assign out = sel ? clk1 : clk0;` 会在切换瞬间产生毛刺（半个窄脉冲），可能让下游触发器误采样。标准电路：**两个时钟域各自用反馈选通寄存器，先关旧、后开新**，保证输出只有完整时钟沿。

```verilog
module glitch_free_mux (
    input clk0, clk1, sel, rst_n,
    output clk_out
);
    reg sel0, sel1;
    // 在 clk0 域：要选 clk0 且 clk1 已关闭，才打开 clk0 通路
    always @(posedge clk0 or negedge rst_n)
        if (!rst_n) sel0 <= 1'b0;
        else sel0 <= ~sel & ~sel1;
    // 在 clk1 域：要选 clk1 且 clk0 已关闭，才打开 clk1 通路
    always @(posedge clk1 or negedge rst_n)
        if (!rst_n) sel1 <= 1'b0;
        else sel1 <= sel & ~sel0;
    assign clk_out = (clk0 & sel0) | (clk1 & sel1);
endmodule
```

原理：切换时旧时钟的选中信号先随自己的时钟沿撤掉（旧时钟完整走完最后一个周期），新时钟的选中信号再随新时钟沿建立，输出永远是"被选通"的完整时钟，没有半沿毛刺。

## 四、跨时钟域（CDC）—— 高频重点

### 4.1 为什么需要 CDC

不同时钟域的触发器（**FF，Flip-Flop**，即 [[FPGA/时序逻辑电路.md|时序逻辑电路]] 里讲的边沿 D 触发器）之间传信号，接收沿可能落在发送信号**亚稳态窗口**内，导致接收 FF 进入亚稳态（输出不定、收敛时间不可预测）。

**亚稳态**：FF（触发器）的 setup/hold 被违反时，输出在 0/1 之间振荡，最终随机收敛。无法消除，只能**降低概率+给时间收敛**。

**MTBF**（平均无故障时间）∝ $\frac{e^{t_{res}/\tau}}{f_{clk} \cdot f_{data}}$。增加收敛时间 $t_{res}$（打两拍）可指数级提高 MTBF。

符号含义：

| 符号 | 含义 |
|------|------|
| $t_{res}$ | 留给亚稳态的**收敛时间**（第一拍时钟沿到第二拍采样沿之间可供振荡平息的时间，打两拍就是给它时间） |
| $\tau$ | 触发器自身的**时间常数**（由工艺决定，越小收敛越快） |
| $f_{clk}$ | 接收端**时钟频率**（越高，每秒可能踩雷的沿越多） |
| $f_{data}$ | 跨域**数据跳变频率**（跳变越频繁，越容易撞上窗口） |

含义：分子是指数项——收敛时间越长，亚稳态能"活下来"的概率指数下降；分母是"踩雷机会"——时钟和数据跳变越频繁，越容易出事。所以**打两拍 = 增大 $t_{res}$ = 指数级提高 MTBF**。

### 4.2 单比特 CDC

单比特跨域的核心矛盾是：**发送域信号的变化节奏与接收域时钟不同步**，要按"谁快谁慢"分两种情况。

#### （1）慢时钟 → 快时钟：两级同步器（打两拍）

慢域信号**保持时间 ≥ 1 个慢周期**，而快时钟在 1 个慢周期内采样很多次，所以快域一定能采到，且能采到稳定值。只需打两拍解决亚稳态：

```verilog
reg [1:0] sync;
always @(posedge clk_fast or negedge rst_n)
    if (!rst_n) sync <= 2'b00;
    else        sync <= {sync[0], data_slow};
wire data_sync = sync[1];   // 同步后的慢域信号
```

- 第一拍可能亚稳态，但到第二拍采样沿前已收敛 → 后级安全。
- **约束**：慢域信号必须保持至少 1 个慢周期（不能是 1 拍窄脉冲），否则快域可能漏采。
- **只解决亚稳态，不解决多比特错位**——多比特不能每位各打两拍（各比特收敛结果可能不一致，拼出错误数据）。

#### （2）快时钟 → 慢时钟：脉冲会丢，必须"变换"

快域的**单周期窄脉冲可能短于慢时钟周期**，慢域两个采样沿之间脉冲就消失了，直接打拍会**整拍漏掉**。两种标准解法：

**解法一：脉冲同步器（toggle 法，推荐）**——快域把"脉冲"变成"电平翻转"，慢域同步电平后**边沿检测**还原脉冲。电平翻转后一直保持，慢域绝不会漏。

```verilog
module pulse_sync (
    input  clk_f, clk_s, rst_n,
    input  pulse_f,        // 快域单周期脉冲
    output pulse_s         // 慢域还原的脉冲
);
    reg toggle;
    always @(posedge clk_f or negedge rst_n)
        if (!rst_n) toggle <= 1'b0;
        else if (pulse_f) toggle <= ~toggle;   // 来一个脉冲翻一次

    reg [2:0] sync;
    always @(posedge clk_s or negedge rst_n)
        if (!rst_n) sync <= 3'b000;
        else        sync <= {sync[1:0], toggle}; // 两拍同步
    assign pulse_s = sync[1] ^ sync[2];          // 边沿检测还原脉冲
endmodule
```

- **约束**：相邻两个快域脉冲的间隔必须 **> 2 个慢周期**（慢域要来得及捕捉每次翻转），否则两次翻转被慢域"看漏"成没变。

**解法二：脉冲展宽 + 应答**——快域把脉冲**展宽成电平**并保持，直到慢域采到并回 ack；慢域对展宽电平打两拍后做上升沿检测得到脉冲。本质是简化版握手，适合脉冲间隔不定的场合。

### 4.3 多比特 CDC

**为什么不能每位打两拍**：各比特的同步 FF（触发器）是独立的，亚稳态收敛结果可能不一致——比如发送 8'b0111_1111→8'b1000_0000，接收端可能读到 8'b0000_0000 等任意中间值。所以多比特必须**保证所有比特在同一时刻被"一致地"采样**，有四类方案：

#### 方案一：格雷码 + 两级同步（连续变化的计数值）

适合**每次只 +1 的计数值/指针**（如 FIFO 读写指针、跨域计数器）。格雷码相邻值只差 1 位，打两拍后接收端读到的**要么是新值要么是旧值**，绝不会是中间的错误组合。

```verilog
// 发送域：二进制 -> 格雷码后跨域
wire [7:0] gray = cnt ^ (cnt >> 1);
// 接收域：两拍同步
reg [15:0] sync;
always @(posedge clk_b) sync <= {sync[7:0], gray};
wire [7:0] cnt_sync = sync[15:8];   // 格雷码值，可直接比较/做指针
```

注意：格雷码同步后**只能用于"单调变化量"的比较**（空/满判断），若需参与算术运算要先转回二进制（二进制转格雷是异或链，可组合实现）。

#### 方案二：握手 req/ack（低速、少量、不连续的数据）

发送域拉 req 并**保持数据不动**，接收域同步 req 后采样数据、回 ack；发送域同步 ack 后才发下一笔。**数据在握手期间完全静止**，从根本上避免错位。

```verilog
// 发送域 A
reg req; reg [7:0] data_hold;
always @(posedge clk_a or negedge rst_n)
    if (!rst_n) {req, data_hold} <= 0;
    else if (vld_a && !req) {req, data_hold} <= {1'b1, data_a};  // 拉req,锁数据
    else if (ack_sync) req <= 1'b0;                              // ack到,释放
// 接收域 B
reg [1:0] req_sync; reg ack; reg [7:0] data_b;
always @(posedge clk_b or negedge rst_n)
    if (!rst_n) {req_sync, ack} <= 0;
    else begin
        req_sync <= {req_sync[0], req};
        if (req_sync[1] && !ack) begin data_b <= data_hold; ack <= 1'b1; end
        else if (!req_sync[1]) ack <= 1'b0;
    end
// ack 再经两拍同步回 A 域得 ack_sync
```

- 优点：简单、绝对安全、不丢数。
- 缺点：**慢**——一笔数据要 req 跨域 + ack 跨域，约 4~6 拍才传一笔，吞吐低。

#### 方案三：异步 FIFO（连续数据流）

数据流速率高、握手喂不饱时用异步 FIFO：**数据不跨域**（写进写域 RAM、从读域 RAM 读出），**只有格雷码读写指针跨域**（各打两拍），用指针比较产生空/满。详见 7.3 节完整结构。

#### 方案四：RAM/寄存器堆 + 地址握手（大数据块）

传输一大块数据（如一帧图像）：发送域把数据写入双口 RAM，写完后**只把"地址/完成标志"跨域**（握手或格雷码），接收域凭地址从 RAM 读。数据始终不跨时钟域。

#### 四种方案对比

| 方案 | 数据类型 | 吞吐 | 硬件成本 | 典型场景 |
|------|----------|------|----------|----------|
| 格雷码+同步 | 单调计数/指针 | 高 | 低 | FIFO 指针、跨域计数器 |
| 握手 | 少量、不连续 | 低 | 低 | 配置寄存器、控制字 |
| 异步 FIFO | 连续流 | 高 | 中（RAM） | 视频流、ADC 采样流 |
| RAM+地址 | 大数据块 | 高 | 中 | 帧缓冲、DMA 式搬运 |

### 4.4 同步 FIFO 与异步 FIFO

#### 同步 FIFO（单一时钟）

读写共用一个时钟，指针用**普通二进制**，空满判断简单：指针位宽 = $\log_2(depth)+1$，**相等即空，最高位相反其余相同即满**。

```verilog
module sync_fifo #(parameter DW=8, DEPTH=16)(
    input clk, rst_n, wr_en, rd_en,
    input  [DW-1:0] wdata,
    output reg [DW-1:0] rdata,
    output full, empty
);
    localparam AW = $clog2(DEPTH);
    reg [DW-1:0] mem [0:DEPTH-1];
    reg [AW:0] wp, rp;
    always @(posedge clk or negedge rst_n)
        if (!rst_n) begin wp <= 0; rp <= 0; end
        else begin
            if (wr_en && !full)  begin mem[wp[AW-1:0]] <= wdata; wp <= wp+1; end
            if (rd_en && !empty) begin rdata <= mem[rp[AW-1:0]]; rp <= rp+1; end
        end
    assign empty = (wp == rp);
    assign full  = (wp[AW] != rp[AW]) && (wp[AW-1:0] == rp[AW-1:0]);
endmodule
```

#### 异步 FIFO（读写两个时钟）

- 结构 = 双口 RAM + 写域逻辑 + 读域逻辑 + **格雷码指针跨域同步**。
- 写地址/读地址用二进制（RAM 寻址），**跨域传的是格雷码指针**。
- **空**（读域判断）：读指针格雷码 == 同步过来的写指针格雷码。
- **满**（写域判断）：写指针格雷码 == {~读指针格雷码[高两位], 读指针格雷码[其余位]}。
- 空满判断因同步延迟而**保守**（判空偏更空、判满偏更满），牺牲一点容量换安全。

#### 对比与选型

| | 同步 FIFO | 异步 FIFO |
|---|---|---|
| 时钟 | 单一 | 读写各一 |
| 指针 | 二进制 | 格雷码（跨域） |
| 空满 | 直接比较 | 格雷码比较，保守 |
| 用途 | 同时钟域内缓冲/速率匹配 | 跨时钟域数据流 |
| 成本 | 低 | 中（多同步器） |

**选型**：同域缓冲用同步 FIFO；跨域数据流必须异步 FIFO（或握手/RAM 方案）。

### 4.5 追问

- **Q：为什么格雷码能用于跨域？** A：每次只变 1 位，接收端即使在该位亚稳态，读到的也只是"新值或旧值"，不会出现中间的错误组合（二进制 0111→1000 四位齐变会读出任意值）。
- **Q：打两拍就一定安全吗？** A：不是，只是把亚稳态概率降到 MTBF 可接受（如>系统寿命）。
- **Q：慢域到快域、快域到慢域分别怎么处理？** A：慢→快打两拍（信号保持≥1 慢周期）；快→慢用脉冲同步器（toggle 法）或展宽+握手，防止窄脉冲漏采。
- **Q：多比特为什么不能每位打两拍？** A：各比特独立收敛可能不一致，拼出错误中间值；必须用格雷码/握手/FIFO 保证一致性。
- **Q：异步 FIFO 空满为什么保守？** A：指针同步有 2 拍延迟，读域看到的写指针"偏旧"，判空会"偏空"、判满会"偏满"，安全但略浪费容量。

## 五、时序分析与约束

### 5.1 建立/保持时间

- **建立时间 $t_{su}$**：时钟沿**前**数据必须稳定的最小时间。违例 → **最高频率上不去**。
- **保持时间 $t_{h}$**：时钟沿**后**数据必须保持的最小时间。违例 → **任何频率都错**（功能性错误）。

**setup 违例解决**：降频、插流水（切组合路径）、优化逻辑级数、提高综合优化。
**hold 违例**：插 buffer 增加路径延迟（与频率无关）。

### 5.2 时序路径与余量

$$T_{clk} \ge t_{co} + t_{comb} + t_{su} + t_{skew}$$

符号含义：

| 符号 | 含义 |
|------|------|
| $T_{clk}$ | **时钟周期**（其倒数即最高工作频率；周期必须大于等于右边总和） |
| $t_{co}$ | 发送端触发器的 **clock-to-output 延迟**（时钟沿到来后，Q 端数据稳定所需时间） |
| $t_{comb}$ | 两级触发器之间**组合逻辑+布线**的总延迟（LUT 级数越多越大） |
| $t_{su}$ | 接收端触发器要求的**建立时间**（数据必须提前于下一个时钟沿稳定的时间） |
| $t_{skew}$ | 时钟到两个触发器的**偏斜**（保守起见加进余量） |

**物理含义**：数据从发送 FF（触发器）出发（$t_{co}$），穿过组合逻辑（$t_{comb}$），必须赶在下一个时钟沿前 $t_{su}$ 到达接收 FF，再预留 skew 余量。右边总和超过 $T_{clk}$ 就 **setup 违例**——所以**降频（加大 $T_{clk}$）或插流水（把 $t_{comb}$ 切小）**是两大解法。
**slack = 要求时间 - 到达时间**；slack>0 满足，slack<0 违例。WNS/TNS：最差/总负 slack。

### 5.3 约束（XDC/SDC）

- `create_clock`：定义时钟周期。
- `set_input_delay / set_output_delay`：IO 时序。
- `set_false_path`：不检查的路径（如跨域、复位）。
- `set_multicycle_path`：多周期路径（慢速逻辑）。

### 5.4 追问

- **Q：什么是 STA？** A：静态时序分析，不仿真、遍历所有路径检查 setup/hold，是签核手段。
- **Q：时序收敛技巧？** A：流水、寄存器重定时 retiming、逻辑重构、布局优化、降扇出。

---

### 5.5 四类时序路径

| 路径类型 | 起点 → 终点 | 约束要点 |
|----------|-------------|----------|
| **reg → reg** | FF → 组合 → FF | 时钟周期约束（最常考，即第 5.2 节公式） |
| **input → reg** | 外部输入 → 组合 → FF | `set_input_delay` |
| **reg → output** | FF → 组合 → 外部输出 | `set_output_delay` |
| **input → output** | 外部输入 → 组合 → 输出 | 约束 IO 组合路径 |

面试常问：时序收敛看的是 **reg→reg** 内部路径；IO 路径由输入/输出延时约束决定。

### 5.6 常用约束怎么写

```tcl
create_clock -period 10 [get_ports clk]                  # 定义 100MHz 主时钟
set_clock_uncertainty 0.2 [get_clocks clk]               # jitter/skew 余量
set_input_delay  2.0 -clock clk [get_ports din]          # 输入相对时钟沿 2ns 到
set_output_delay 1.5 -clock clk [get_ports dout]
set_false_path -from [get_clocks clk_a] -to [get_clocks clk_b]  # 异步跨域，不检查
set_multicycle_path 2 -setup -from [get_pins ...] -to [get_pins ...]  # 慢速路径允许 2 周期
```

### 5.7 怎么看时序报告

- **WNS（最差负余量）/ TNS（总负余量）**：负值即违例；WNS 是最差那条路径的 slack。
- **Critical Path**：报告里 slack 最小（红）的路径就是瓶颈，先看它。
- 修复顺序：先查 **reg→reg** 数据通路（最影响频率），再看 IO 路径；setup 用流水/降频，hold 交给工具 + 必要时插 buffer。

## 六、状态机与序列检测

### 6.1 三段式状态机（推荐写法）

- 第一段：时序，状态寄存器更新。
- 第二段：组合，次态逻辑。
- 第三段：时序（或组合），输出。

优点：结构清晰、无 latch、输出可寄存消毛刺。

### 6.2 Moore vs Mealy

- Moore：输出只与状态有关，输出稳定但状态多。
- Mealy：输出与状态+输入有关，状态少但输出随输入毛刺。

### 6.3 状态编码

| 编码 | 特点 |
|------|------|
| 二进制 | 省 FF（触发器），但多位齐变 |
| 格雷码 | 单比特变化，省功耗 |
| 独热码 one-hot | 一状态一 FF（触发器），译码简单、速度快，FPGA 常用（FF 多 LUT 少） |

### 6.4 经典题：序列检测 1011（可重叠，Moore）

状态：S0(无)→S1(1)→S2(10)→S3(101)→S4(1011,输出1)。重叠关键：S4 收到 1 去 S1，收到 0 去 S2（"10"可复用）。

```verilog
module seq1011 (
    input clk, rst_n, din,
    output reg det
);
    localparam S0=0,S1=1,S2=2,S3=3,S4=4;
    reg [2:0] st, nst;
    always @(posedge clk or negedge rst_n)
        if (!rst_n) st <= S0; else st <= nst;
    always @* begin
        case (st)
            S0: nst = din ? S1 : S0;
            S1: nst = din ? S1 : S2;
            S2: nst = din ? S3 : S0;
            S3: nst = din ? S4 : S2;
            S4: nst = din ? S1 : S2;
            default: nst = S0;
        endcase
    end
    always @(posedge clk or negedge rst_n)
        if (!rst_n) det <= 0; else det <= (nst == S4);
endmodule
```

（已验证：输入 101011011 在两个 1011 结尾正确输出。）

## 七、存储资源：RAM / ROM / FIFO

### 7.1 BRAM vs 分布式 RAM vs 寄存器堆

| | BRAM | 分布式 RAM | 寄存器堆（FF（触发器）array） |
|---|---|---|---|
| 容量 | 大（36Kb/块） | 小 | 极小 |
| 读 | 同步（1拍延迟） | 异步 | 异步 |
| 成本 | 专用资源 | 占 LUT | 占大量 FF（触发器） |

### 7.2 FIFO 深度计算（必考）

**核心**：FIFO 深度 = 突发期间"写入量 - 读出量"的最大值。

**例 A**：写 100MHz 背靠背突发 200 个数据，读 80MHz 连续。突发时间 $T=200/100M=2\mu s$，期间读 $80M \times 2\mu s=160$，深度 $=200-160=40$。

**例 B**：写 100MHz 背靠背突发 100 个数据，读 50MHz 连续。突发时间 $T=100/100M=1\mu s$，期间读 $50M \times 1\mu s=50$，深度 $=100-50=50$。

**通用公式**（突发写、连续读）：
$$depth = B - f_{read} \cdot \frac{B}{f_{write}}$$

符号含义：

| 符号 | 含义 |
|------|------|
| $B$ | **突发长度**（最坏情况下连续写入的数据个数） |
| $f_{write}$ | 突发期间的**写速率**（个/秒），$\frac{B}{f_{write}}$ 即突发持续时间 |
| $f_{read}$ | **连续读速率**（个/秒），乘突发时长得期间读走的量 |

含义：突发期间写进来的减去读走的，就是 FIFO 里**净积累峰值**，深度至少要等于它。若写是稀疏使能（如每 N 拍写 M 个），先换算成"最坏连续突发"再套公式。

### 7.3 异步 FIFO 结构（格雷码指针）

- 写域：写指针（二进制+格雷码），写地址用二进制。
- 读域：读指针同理。
- 格雷码指针**打两拍**跨域。
- **空**：读域比较 `rgray == rgray_w_sync`（相等）。
- **满**：写域比较 `wgray == {~rgray_sync[N-1:N-2], rgray_sync[N-3:0]}`（高两位取反、其余相同）。
- 指针位宽 = $\log_2(depth)+1$（多一位区分空/满）。其中 $\log_2(depth)$ 是寻址 depth 个位置所需位数；**多出的 1 位**用于区分空和满——读写指针"完全相等"是空，"最高位相反、其余相同"是满，没有这一位两者无法区分。

（空/满判断已程序验证。）

### 7.4 追问

- **Q：为什么异步 FIFO 用格雷码不用二进制？** A：指针跨域是"多比特"，二进制多位齐变会错位；格雷码单比特变化，同步后只可能差一格，空满判断安全。
- **Q：空满判断为什么保守？** A：同步有延迟，判空偏"更空"、判满偏"更满"，牺牲一点容量换安全。

## 八、经典电路模块

### 8.1 边沿检测（上升沿）

```verilog
reg [1:0] d;
always @(posedge clk) d <= {d[0], sig};
wire pos = d[0] & ~d[1];
```

### 8.2 按键消抖

机械按键抖动 ~5-20ms。方法：两级同步 + 计数器计满（如 20ms）才认电平变化。

```verilog
// key_sync 为按键经两级同步后的信号
reg [19:0] cnt; reg key_r; reg key_out;
always @(posedge clk) begin
    if (key_sync != key_r) begin cnt <= 0; key_r <= key_sync; end
    else if (cnt != 20'd999_999) cnt <= cnt + 1;
    else key_out <= key_r;   // 稳定 20ms 后输出
end
```

### 8.3 偶数分频 / 奇数分频

- **偶数分频**：计数器计到 N/2-1 翻转，占空比 50%。
- **奇数分频（50% 占空比）**：上升沿计数得 clk_p + 下降沿计数得 clk_n，两者**或**起来。

```verilog
module div3 (input clk, rst_n, output clk_out);
    reg [1:0] cnt_p, cnt_n;
    always @(posedge clk or negedge rst_n)
        if (!rst_n) cnt_p <= 0; else cnt_p <= (cnt_p==2)?0:cnt_p+1;
    always @(negedge clk or negedge rst_n)
        if (!rst_n) cnt_n <= 0; else cnt_n <= (cnt_n==2)?0:cnt_n+1;
    assign clk_out = (cnt_p==0) | (cnt_n==0);
endmodule
```

（已验证：周期=3 个 clk，占空比 50%。）

### 8.4 脉冲跨域（快→慢展宽，慢→快同步）

- 慢→快：打两拍 + 边沿检测还原脉冲。
- 快→慢：快域**展宽**到慢域能采到（>=慢周期），慢域采样后快域再**清零**（握手）。

### 8.5 握手（req/ack）

发送域拉 req 并保持数据，接收域同步 req 后采样数据并回 ack，发送域同步 ack 后撤 req。可靠但慢（多拍）。

## 十二、运算电路：加法器与乘法器

### 12.1 加法器

- **半加器**：$S=A\oplus B$，$C=AB$（不考虑进位）。
- **全加器**：$S=A\oplus B\oplus C_{in}$，$C_{out}=AB+C_{in}(A\oplus B)$。
- **多位加法**两种实现：
  - **行波进位（Ripple Carry）**：全加器级联，进位逐级传——n 级延迟，速度慢、面积小。
  - **超前进位（Carry Look-ahead, CLA）**：并行产生进位，快。定义生成 $G=AB$、传播 $P=A\oplus B$：
    $$C_{i+1} = G_i + P_i C_i,\qquad C_2 = G_1 + P_1G_0 + P_1P_0C_0$$
    n 位延迟接近常数，但面积大、扇出大。
- **FPGA 实际**：多位加法直接用 `+`，综合器自动选进位链/资源；手撕题常考"用门搭 1 位全加器、搭 4 位加法器"。

### 12.2 乘法器

| 类型 | 原理 | 特点 |
|------|------|------|
| **阵列乘法器** | 与门生成部分积 + 加法器树累加 | 全组合、面积大、延迟长 |
| **Booth 编码** | 对乘数编码（每 2~3 位一组）减少部分积个数 | 适合补码/硬件乘法器 |
| **流水乘法器** | 加法器树切成多级流水 | 提高吞吐，结果晚 N 拍 |
| **DSP48** | FPGA 专用乘累加硬核 | `*` 综合到 DSP48，省 LUT、快 |

手撕常考：4 位乘法器展开 / 用加法器搭乘法器 / DSP48 优势。

> **位宽与溢出**：两 n 位无符号数相乘 = 2n 位；相加最大 n+1 位。加减乘前先想清位宽，防截断丢数据——面试常问"会不会溢出、怎么处理"。

## 十三、低功耗设计

### 13.1 功耗构成

- **动态功耗**（占大头）：$P_{dynamic} = \alpha C V_{DD}^2 f$（α=翻转率，C=负载电容，f=频率，V=电压）。
- **静态功耗**：漏电流，工艺越小越显著（先进工艺占比升高）。

### 13.2 降功耗手段（高频）

| 手段 | 原理 |
|------|------|
| **时钟门控** | 空闲模块关时钟，省掉全部翻转功耗（最有效） |
| **操作数隔离** | 数据无效时把运算输入锁成 0，避免无效翻转 |
| **使能信号** | 只让需要的寄存器翻转 |
| **格雷码** | 计数器/状态机相邻只变 1 位，少翻转 |
| **DVFS / 降电压** | 功耗与 $V^2$ 成正比，降压最划算 |
| **降频 / 流水** | 降低翻转频率，或流水让每级翻转率下降 |

面试记忆点：**动态功耗跟 $V^2$、f、翻转率成正比**——所以降功耗第一招是"少翻转"（门控/使能/格雷码），第二招是"降电压"。

## 十四、接口协议速览

### 14.1 AXI 总线（AMBA）

- **AXI4**：5 通道——写地址 AW、写数据 W、写响应 B、读地址 AR、读数据 R。每通道 **valid/ready 握手**：源拉 valid、目的拉 ready，两者同时为高才传输一拍。
- **AXI4-Lite**：简化版，单次传输，多用于寄存器配置。
- **AXI4-Stream**：无地址的纯数据流（valid/ready），用于 FIFO 式搬运。
- 常问：握手规则（valid 不能依赖 ready）、突发 burst、乱序/outstanding。

### 14.2 串行协议一句话要点

| 协议 | 时钟 | 双工 | 要点 |
|------|------|------|------|
| **UART** | 异步（约定波特率） | 全双工 | 起始位+数据+停止位 |
| **SPI** | 同步（SCK） | 全双工 | 4 线，CPOL/CPHA 4 种模式 |
| **I2C** | 同步（SCL） | 半双工 | 2 线开漏，地址+读写，应答位 |

详见 [[FPGA/UART串行通信协议.md|UART]]、[[FPGA/SPI串行通信协议.md|SPI]]、[[FPGA/I2C串行通信协议.md|I2C]]。

## 十五、Verilog 进阶易错点

### 15.1 if / case / casez / casex

- `if`：有优先级（级联 if 综合出优先级逻辑链）；`case`：无优先级（综合成并行 MUX）。
- `casez`：把 `?`/`z` 位当无关项；`casex`：`x`/`z` 都当无关项。**慎用**（仿真/综合语义有差异）。
- 都建议补 `default`（避免推断 latch，见二章）。

### 15.2 位宽与符号

- 位宽不足会**截断**；高位自动补 0。
- 无符号与有符号混用按"较长 + 无符号"规则处理，易出错。
- 有符号写法：`reg signed [7:0] a;`、`$signed(b)`、算术右移 `>>>`。
- 溢出检测：两同号相加结果异号 = 溢出；乘法看高半部分是否为全 0/全 1。

### 15.3 其他易错

- `integer` 综合成 32 位寄存器；`for` 可综合（会展开），`while` 慎用。
- `parameter` 可被上层 `#()` 覆盖，`localparam` 不可；`\`define` 是全局宏。
- `initial` 不可综合（仅仿真初始化），FPGA 靠复位赋初值。
- x/z 来源：未初始化、未连接、多驱动——仿真里 X 会传播难查，综合后多为不定/0。

## 十六、面试技巧与延伸

- **回答结构化**：先给定义，再讲原理，再给 Verilog/例子，最后说 trade-off。
- **主动画状态图/时序图**：白板题先画图再写码。
- **常问项目**：准备 1-2 个深挖项目（如 UART/FIFO/FFT），讲清指标、难点、时序。
- **延伸准备**：AXI 协议（5 通道、valid/ready 握手）、DDR 基础、UART/SPI/I2C（见 [[FPGA/UART串行通信协议.md|UART]]、[[FPGA/SPI串行通信协议.md|SPI]]、[[FPGA/I2C串行通信协议.md|I2C]]）、FFT/滤波（见 [[信号处理/数字下变频（DDC）.md|DDC]]）。
